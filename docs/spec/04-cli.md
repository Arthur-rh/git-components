# CLI Specification

## Command form

> *Note on git subcommands: When invoked as `git <subcommand>`, Git executes `git-<subcommand>` (or the platform equivalent) if present on PATH.*

The executable of the tool **shall** be named `git-component` on UNIX based systems, and `git-component.exe` on Windows based systems

The tool **shall** be invoked as a Git-style subcommand:

```bash
git component <subcommand> [options]
```

The tool **shall** support direct invocation:

```bash
git-component <subcommand> [options]
```

Both forms **shall** behave identically.

## Global behavior

### Working directory

Commands operate on the current repository and expect `.git-components.yml` in the repository root unless otherwise specified.

### Repository root discovery

The tool **shall** determine the repository root using Git and interpret manifest and lock paths relative to that root.
If no git repository is found, an error **shall** be returned (see *Error codes*)

### Output streams

- normal informational output: stdout
- warnings and errors: stderr

### Non-interactive use

Commands **shall** be suitable for CI and scripts, if there is an interactive command, an option **shall** be present to suppress this behavior.

### Git commit hash resolution

When `branch` or `tag` selectors are used, the tool **shall** resolve the selector to an exact commit hash before importing, and the resolved commit hash **shall** be recorded in the lock

### Credentials

The tool **shall** use `git` credentials

### `.gitignore` handling

- The tool adds all pulled files into the current repository `.gitignore` by default.
- When pulling new files, first remove all entries from the `.gitignore` corresponding to current imported files before re-adding them at the end of the pull.
- All files added to the `.gitignore` automatically by the tool **shall** have a comment next to the entry that references the component and rule that imported it. 
  - The comment **shall** be used to identify which entries in the `.gitignore` were generated by the tool.
  - The comment **shall** start at the line (required by `.gitignore`) right above the path to the associated file.
  - The comment **shall** have the format `# <component>@<source>:<destination>` where `<source>` and `<destination>` come from the rule that imported the corresponding file
- The `.gitignore` entires block **shall** start with a header in the format :
```gitignore
#==== GENERATED BY GIT COMPONENTS ====
# DO NOT MODIFY
<blank line>
```
- The `.gitignore` entires block **shall** end with a footer in the format :
```gitignore
<blank line>
#==== END OF COMPONENTS ====
```
- All entries **shall** be placed at the end of the `.gitignore`

Example:
```gitignore
/build
/manual/entries

#==== GENERATED BY GIT COMPONENTS ====
# DO NOT MODIFY

# component1@/src:/dest
/dest/path/to/file.md

#==== END OF COMPONENTS ====
```

## Global options

Recommended global options:

- `--manifest <path>`  
  - Override path to `.git-components.yml`

- `--lock <path>`  
  - Override path to `.git-components.lock`

- `--verbose`  
  - Increase diagnostic output

- `--strict`
  - Treat warnings as errors

## Local modifications

Every imported component **shall** be in read-only, when pulling, if the file was modified (read-only removed and modified knowingly), the user can be notified that his changes would be overwritten.

Also see *File change detection* `03-lock-format.md`

## Subcommands

Version 1 **shall** define the following subcommands:

- `help`
- `init`
- `add`
- `remove`
- `pull`
- `prune`
- `list`
- `status`
- `resolve`

The following subcommands are planned for later releases

- `order`

## Subcommand summary

### `help`
Displays help on how to use the tool.

### `init`
Creates an initial manifest file.

### `add`
Adds a component into the manifest

### `remove`
Removes a component from the manifest, without removing the files present locally (neither the lock entry), prompts the user to use `prune` to remove components waiting to be removed (present in lock but not in manifest) 

### `pull`
Updates the components, if the reference used is a branch or tag, resolve the commit hash and notice the user that the commit hash was modified, prompts the user if they wish to continue.

### `prune`
Removes all files from components that were removed from the manifest (either manually or by `remove`)

### `list`
Lists configured components.

### `status`
Similar to `git status`, displays:
- if the commit has changed (for branches/tags)
- components waiting to be `pruned`
- if there is local modifications on the component

### `resolve`
Rebuilds lock, resolve commit hashes of branch/tag without pulling the components

### `order` ***TBD***
Changes the load order of the components

## Error codes

### Successes

- `0`: success

### General errors

- `1`: argument validation error
- `2`: the command is not running inside an existing git repository
- `3`: Git failure
- `4`: any other filesystem error
- `5`: the given regex/glob pattern is not valid
- `6`: the specified command was unknown
- `7`: files were modified locally since last pull, and `--force` is not used
- `8`: unexpected usage of option `--filter-glob/filter-re/exclude-glob/exclude-re pattern`

### Reserved

- `9`: reserved
- `10`: reserved
  
### Component errors

- `11`: component is already present, and `--force` is not used
- `12`: component does not exist, and `--silent` is not used
- `13`: two components/rules tried importing a file in the same path (strict-mode)

### Reserved

- `14`: reserved
 
### Manifest errors

- `15`: manifest and lock disagree, and `--update-lock` is not used
- `16`: manifest already exists, and `--force` is not used
- `17`: the manifest does not exist or is not initialized
- `18`: the manifest exists but could not be read, or its content is invalid (see `02-manifest-format.md`)
- `19`: the manifest exists but could not be edited
- `20`: the manifest could not be created

### Lock errors

- `21`: the lock does not exist or is invalid
- `22`: the lock exists but can not be read
